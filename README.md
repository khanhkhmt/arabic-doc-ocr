# arabic-doc-ocr

OCR for old Arabic legal documents (1970s contracts, powers of attorney, official letters): **printed and
handwritten** Arabic on yellowed paper with stamps, signatures, fingerprints and Hebrew notary blocks.
Output is a **draft for a person to check**: every word where two independent readers disagree is highlighted.

```
page ─► dots.mocr: layout blocks + printed text (page enlarged to 2400 px)
     ─► Kraken + Muharaf model: text lines of the whole page, assigned to the dots blocks
        (line images made 50 % taller along the line shape: handwritten page 2 72.2 → 78.0 %, see below)
     ─► Baseer-Nakba + LoRA ft3 reads every line, ft4 reads it again (cross-check)
     ─► main text per block:  handwritten page → ft3        printed page → dots (ft3 cross-checks)
                              Hebrew block → dots text (not checked)   stamp / signature / fingerprint → picture
     ─► DOCX (yellow + Word comments where readings differ), TXT, review HTML, JSON, page images
```

## Accuracy (sample pages, correct characters)

| page | content | main text |
|---|---|---|
| 1 | typed contract | dots 90.3 % |
| 2 | handwritten contract, blue ballpoint | ft3 72.6 % |
| 3 | typed power of attorney + stamps + Hebrew block (Hebrew not scored) | 79.0 % |
| 4 | typed official letter + handwritten notes + watermark | dots 90.9 % |

Line test sets (500 lines each): ft3 93.4 % (Omar Al-Saleh 1951–65), 94.7 % (Muharaf, unseen writers),
91.4 % (Muharaf test). Cross-check highlighting marks 13–19 % of words and catches 57–75 % of the wrong ones —
words that are not highlighted can still be wrong (above all digits, names, dates).
The numbers of the latest run on a GPU server are in **[docs/RESULTS.md](docs/RESULTS.md)**.

## System requirements

Expected (the measured numbers and how they are derived are in
**[docs/SYSTEM_REQUIREMENTS.md](docs/SYSTEM_REQUIREMENTS.md)**, generated by `scripts/run_all.sh` — that file wins):

- Linux, NVIDIA GPU (compute capability ≥ 7.5, e.g. T4 / L4 / A10 / RTX 30xx–40xx / A100), driver ≥ 525, Python ≥ 3.10
- minimum: **one 16 GB GPU** (the two models take turns on it — slower); recommended: **two 16 GB GPUs or one 24 GB GPU**
- ~25 GB disk (models ~13 GB + virtualenvs), internet for the first model download
- no GPU → not supported (dots.mocr is impractically slow on a CPU)

## Install

```bash
git clone https://github.com/khanhkhmt/arabic-doc-ocr.git && cd arabic-doc-ocr
bash install.sh                      # .venv + Kraken venv + segmentation model + all models (~15 GB download)
.venv/bin/python -m arabic_doc_ocr check     # must end with "OK"
```

`install.sh` reuses a CUDA torch that is already installed (Colab, Kaggle, NVIDIA/PyTorch docker images) and never
replaces it; otherwise it installs torch from PyPI. **transformers is pinned to 4.56.1** (tested; other versions
changed dots.mocr / Qwen2.5-VL generation). Kraken gets its own virtualenv because it pins its own torch.

## Use

```bash
# web interface on http://127.0.0.1:7862 (remote server: ssh -L 7862:127.0.0.1:7862 <server>)
bash run_web.sh

# command line: one --type for all files, or one per file
.venv/bin/python -m arabic_doc_ocr page scan.pdf --type printed --out results/
.venv/bin/python -m arabic_doc_ocr page a.jpg b.jpg --type handwritten,printed --pages 1-3 --out results/
.venv/bin/python -m arabic_doc_ocr line line1.png line2.png --json lines.json
```

`--type`: **handwritten** (ft3 gives the main text), **printed** (dots gives the main text — ft3 only reaches ~80 %
on typewritten text). A page that is mostly typed with a few handwritten notes → printed.

GPUs: by default dots runs on `cuda:0` and the line reader on `cuda:1` if present. With one GPU, `--offload auto`
keeps both models on it if it has ≥ 22 GB, otherwise only the model in use stays on the GPU — the other is moved to
CPU RAM (`--offload cpu`, needs more RAM) or freed and reloaded (`--offload unload`, ~1 min per swap). A document is
processed in two passes (layout of all pages, then all lines), so the models swap once per document.

Line images: `--line-pad 50` (default, `config.LINE_PAD_PCT`) makes every Kraken line image taller by 50 % of the
line thickness (half above, half below, following the line polygon), so ascenders, descenders and dots cut off
by the segmentation are kept. Measured in ocr-bench (2026-10-23, ft3 on Kraken lines of 66 Muharaf test pages):
0 % 63.6 · 15 % 65.6 · 30 % 66.7 · 50 % 67.2 % correct characters; sample page 2: 72.2 → 78.0 %.
`--line-pad 0` = the line crop of the 2026-10-19 results. Check on a GPU server: `bash scripts/check_pad50.sh`.

Python:

```python
from arabic_doc_ocr.pipeline import Pipeline, load_pages
from arabic_doc_ocr.export import write_all
pipe = Pipeline()                                  # or Pipeline("cuda:0", "cuda:1")
results = pipe.process_document(load_pages("scan.pdf"), page_type="printed")
write_all("out/", "scan", results)
print(results[0].page_text("main"))
```

## Optional: LLM correction

After the OCR, an LLM (**Qwen3.5-9B**, Apache 2.0) can fix letter-level OCR mistakes. Off by default.

```bash
bash install_llm.sh                          # own venv (transformers 5.15.1) + model (~18 GB); after install.sh
.venv/bin/python scripts/check_llm.py        # optional: re-run the measured check on the 4 sample pages
# web: tick "LLM correction"   ·   CLI: add --llm
.venv/bin/python -m arabic_doc_ocr page scan.pdf --type printed --llm --out results/
```

- Method (fixed, measured on the 4 sample pages, 2026-10-19): where the two readings of a block differ, the LLM keeps
  the more probable one; then it proposes corrections, and only 1-word ↔ 1-word changes of ≤ 2 letters (≤ 40 % of
  the word, no digits) are accepted. It never adds, drops or reorders words and never changes numbers.
- Measured: printed pages +1.1…+3.0 % correct characters (+8…+13 % correct words), handwritten page +3.0 % (+5.3 %
  words); 89 words fixed, 12 broken. Only 4 pages — a signal, not a guarantee.
- Changed words are **green** in the DOCX (comment = what the OCR read) and in the review table; `_ocr.txt` and the
  JSON (`text_ocr`, `llm_changes`) keep the text before the correction. Check green words too.
- Needs ≥ 22 GB GPU memory in total (2 × T4 works, one T4 does not). The OCR models are freed while the LLM runs and
  reloaded for the next document: +1–2 min to load the LLM, ~1 min per page.

## Output files

| file | content |
|---|---|
| `<name>_all.zip` | everything below |
| `<name>.docx` | main text in reading order; words the cross-check reads differently in **yellow** with a Word comment; stamps / signatures as pictures; one page break per page |
| `<name>_main.txt` | main text; `_ft3.txt`, `_ft4.txt`: each line reader alone |
| `<name>_ocr.txt` | only with the LLM step: main text before the correction (green words in the DOCX = changed) |
| `<name>_review.html` | line by line: line image, ft3 with highlights, ft4 (open in a browser) |
| `<name>.json` | blocks and lines with boxes (pixels of the prepared page) and every reading, timings, notes |
| `<name>_pN_boxes.jpg` | page with dots blocks (blue, Hebrew purple) and lines (green = both readers agree, orange = differ) |

## Limits — read before use

- Handwriting: ~73 % correct characters on a real 1970s page — the text must be checked against the image.
- Digits, amounts, dates and names are the weakest part. Check every number (e.g. an amount written in figures
  against the same amount written in words).
- Hebrew blocks are kept as dots reads them and are not checked. Handwritten notes inside areas dots labels as a
  picture (stamps, margins) are not read.
- Phone photos sent as "photo" in messaging apps are compressed; ask for the original file ("document").
